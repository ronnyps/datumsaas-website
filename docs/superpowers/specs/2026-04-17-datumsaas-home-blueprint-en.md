# DatumSaaS Home Blueprint (EN)

## Scope
Homepage structure and copy strategy for mid-market companies across sectors, using clear non-technical language.

Primary objective:
- Position DatumSaaS as an all-in-one real operating system.

Secondary objective:
- Drive qualified strategic demo meetings without aggressive sales pressure.

---

## Writing Rules for This Homepage

- Use simple business language.
- Avoid technical jargon unless absolutely necessary.
- Keep one core idea per section.
- Show operational outcomes before product mechanics.
- Keep examples sector-neutral so any business can relate.

---

## 1. Header

### Purpose
Create instant orientation and trust.

### Copy
- Nav: `Platform`, `How It Works`, `Why DatumSaaS`, `Security`, `Documentation`
- Primary CTA: `Book a Strategic Demo`

### How To Demonstrate This Section
- Keep header clean, sticky, and highly legible.
- Add a subtle status pill near CTA: `Built for growing teams`.
- On hover, keep micro-motion minimal and professional.

---

## 2. Hero (Attention)

### Purpose
State the core value in plain language: one system replaces disconnected tools.

### Copy
- Headline: `One System to Run Your Entire Business`
- Subheadline: `Manage leads, daily work, sales, payments, and reporting in one place, so your team stays aligned as you grow.`
- Primary CTA: `Book a Strategic Demo`
- Secondary CTA: `See How It Works`
- Micro trust line: `No obligation. Practical walkthrough based on your real operation.`

### How To Demonstrate This Section
- Show a short animated product flow strip:
  - `Lead -> Task -> Sale -> Payment -> Report`
- Use real UI screenshots with subtle transitions.
- Add one “before vs after” visual:
  - Before: scattered tools
  - After: one connected workflow

  - `Task Scheduling`

## 4. Problem Narrative (Fragmentation Cost)

### Purpose
Make the pain obvious for broad mid-market audiences.

### Copy
- Title: `When Your Tools Are Disconnected, Growth Gets Harder`
- Body: `Teams work in different systems, data does not match, and decisions slow down. As operations grow, control gets harder instead of easier.`
- Bullet outcomes:
  - `Missed handoffs between teams`
  - `Repeated manual work`
  - `Limited visibility across operations and finance`

### How To Demonstrate This Section
- Split-panel visual:
  - Left: disconnected apps and broken process arrows
  - Right: single connected operational map
- Add simple “time lost” counters to make the pain tangible.

---

## 5. System Flow (Interest)

### Purpose
Show the end-to-end business journey in one system.

### Copy
- Title: `From First Contact to Final Report, In One Flow`
- Intro: `DatumSaaS keeps every step connected so teams can execute faster and leaders can decide with confidence.`
- Steps:
  1. `Capture and qualify opportunities`
  2. `Assign and track work`
  3. `Create orders and proposals`
  4. `Manage payments and status`
  5. `Review performance in real time`

### How To Demonstrate This Section
- Build a horizontal interactive timeline.
- Each step reveals a real screenshot and short plain-language tooltip.
- Include “what changes” micro line under each step:
  - Example: `No double entry needed`

## 10. FAQ (Objection Handling)

### Purpose
Answer core concerns in plain language.

### Copy
- Q: `Do we need to replace everything at once?`
  - A: `No. Teams usually start with the most urgent workflow and expand in phases.`
- Q: `Is this only for one type of business?`
  - A: `No. DatumSaaS is designed for growing companies across sectors that need operational clarity and control.`
- Q: `Will this be too complex for our team?`
  - A: `The system is structured to simplify daily execution, not add more complexity.`
- Q: `Can leadership and teams use the same system without confusion?`
  - A: `Yes. Teams execute in their area while leadership sees a unified business view.`

### How To Demonstrate This Section
- Use clean accordion with short answers.
- Add small “common concern” labels for scanability.
